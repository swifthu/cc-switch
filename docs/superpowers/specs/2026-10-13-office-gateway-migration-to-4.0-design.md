## 目标

把 swifthu/cc-switch v3.20.4 上的 office-gateway 功能（PR #5045 引入）以及用户自加的 gateway_token 显示增强（6 commit）迁移到 farion1231/cc-switch v4.0.10（4.0 上游）。

## 关键事实

1. **farion 4.0 与 swifthu 3.20.4 是不同 fork**：merge-base 仅 `1ee2fdc3`，4.0 几乎完全重写（UI 侧边栏、聚合模式、新 provider 抽象）。
2. **office-gateway 在 4.0 完全不存在**：完全没有 office 概念；用户需从零重建。
3. **office-gateway 在 3.20.4 是独立子功能**：单文件 `office_gateway.rs`（2113 行），不依赖 `proxy/*` 模块、不用 DB，自有 `app_config_dir/office-gateway/config.json` 持久化。

## 架构决策

### 不复用 4.0 proxy 模块

office-gateway 保持**完全独立**：
- 独立 axum Router，独立端口（`127.0.0.1:8790`）
- 独立 `OfficeGatewayService`、独立 `app.manage(OfficeGatewayState(...))`
- 独立 `app_config_dir/office-gateway/config.json` + 环形缓冲日志
- 不走 4.0 的 `ProviderRouter` / `RequestForwarder`

参照 4.0 已有的 `/claude-desktop/v1/...` 模式（独立 `claude_desktop_config.rs`），office-gateway 走同款"独立 service + commands 子模块"模板。

### gateway_token 显示：懒加载（反 4.0 设计）

- **4.0 原生设计**：`ClaudeDesktopStatus.gateway_token_configured: bool`（不显示 token 字符串）
- **本任务决定**：保留 swifthu 3.20.4 用户的"可复制 token"语义
- **实现方式**（避免公开结构暴露明文）：
  - 新增 `#[tauri::command] reveal_claude_desktop_gateway_token`
  - 调 `claude_desktop_config::get_or_create_gateway_token` 拿 token
  - DesktopAccessBar 加"显示 Token"按钮，按下时才调命令
  - UI 限制：`mode === "proxy" && gatewayTokenConfigured` 时才显示

## 数据流

```
Client (Office / Excel Claude add-in)
  └─ POST http://127.0.0.1:8790/v1/messages
       └─ messages() axum handler
            ├─ resolve_route(config, headers)  →  Route
            ├─ sanitize_request(body, config)
            │   ├─ 字段白名单 + DeepSeek 去 thinking
            │   ├─ custom tool 折叠为裸 {name, description, input_schema}
            │   ├─ tool_choice "custom" → "tool"
            │   └─ probe 抬升 max_tokens
            ├─ route_model 重写
            ├─ reqwest POST upstream_url
            └─ stream ? sse_shim_stream(bytes_stream) : text() → 透传
```

## 数据存储

- `<app_config_dir>/office-gateway/config.json`：`OfficeGatewayConfig` 序列化（不依赖 DB）
- `<app_config_dir>/office-gateway/office-gateway.log`：环形缓冲 600 + 落盘

## 关键技术挑战

### NFS 资源 fork 污染

- **症状**：macOS 客户端访问 `/Volumes/CC`（Synology NFS 挂载）时为每个文件产生 `._*` 资源 fork；tauri 2.x build.rs 读 `target/.../autogenerated/*.toml` 时 panic。
- **根因**：4.0 的 tauri 2.10.3 + macOS 升级后 SMB 客户端行为；swifthu 3.20.4 时代 9 月底未出现。
- **解决**：`CARGO_TARGET_DIR=~/ccswitch-target` 把 cargo 编译输出移到本地 APFS SSD；`scripts/cargo-check-clean.sh` wrapper 默认应用此设置。

### tauri 2.10.3 → 2.8.2 锁版

- **症状**：tauri 2.10.3 build.rs 在 macOS NFS 上稳定 panic；2.8.2 也复现。
- **决策**：Cargo.toml 锁 `tauri = "=2.8.2"` + `tauri-build = "=2.4.0"`，与 3.20.4 配套。4.0 没用到 2.9/2.10 新 API。
